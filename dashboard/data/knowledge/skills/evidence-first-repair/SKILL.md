출처: 프로젝트 AGENTS.md와 2026-10-19 사용자가 승인한 프로젝트 기억 초기화 요구. 초기 절차 문서이며 자동 학습 완료 주장이나 벤치마크 데이터가 아니다.

1. 사용자가 보는 화면에서 실패한 요청의 URL, HTTP 상태, 응답 스키마를 확인한다.
2. 실제 서비스 포트와 API 라우터를 확인한다. 실패 응답을 빈 데이터나 정상 상태로 해석하지 않는다. 백엔드를 채택하기 전에 HTTP 성공 상태와 응답의 nodes/edges 스키마를 검증한다.
3. 선택한 백엔드를 읽기와 편집에 일관되게 사용한다. PATCH/DELETE 재시도 때 다른 백엔드로 전환하지 않는다. revision 충돌(409) 시 초안 편집을 보존한다.
4. 원본 데이터와 변경 전 해시를 확인한다. 기존 노드·원장·파일을 삭제하거나 숫자를 맞추기 위해 생성하지 않는다.
5. 최소 범위 수정 후 같은 경로에서 HTTP 응답과 실제 화면을 검증한다.
6. 검증한 결과와 미확인 범위를 분리해 기록한다. 재사용 가능한 교훈만 기존 절차에 부분 반영한다.

## 에고라이트 네이티브 스페이스 조작 표준
1. 브라우저 점검·벤치마킹·세션 확인 시 별도 브라우저 창을 강제 팝업(`SetForegroundWindow`)하지 않고 `dashboard/common/ego_taskspace.py`를 통해 에고라이트 네이티브 `TaskSpace`(`Profile 3`~`Profile 7`, `Default`)에서 백그라운드로 수행한다.
2. 일반 DOM 탐색은 `page.snapshot()` 및 `semantic_snapshot()`을 우선 사용하고, 작업 종료 시 반드시 `await task.finish({ keep: [] })`로 스페이스를 닫아 탭 누수를 방지한다.
3. 2차 인증·캡차·로그인 풀림 감지 시 억지 클릭을 멈추고 즉시 `handoff_to_ceo()`(`await task.handOff()`)를 호출해 대표님께 스페이스 제어권을 인계한다.

## 성공 근거
실제 요청 URL·상태, 변경 전후 결과, 실행한 회귀 검증을 함께 남긴다. 스크린샷이나 파일 경로만 존재하는 것은 기능 성공의 증거가 아니다.
