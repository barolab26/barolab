# 네이버 콘텐츠 운영·검수 절차

갱신일: 2026-10-21. 계정별 독자·말투·공개 링크 정책은 `soul.md`와 실행 설정을 유지한다. 이 문서는 편집 품질과 검증 기준이며 검색 노출 보장 공식이 아니다. 실제 실행 스키마·안전 게이트와 함께 적용한다. 아래 과거 `posting.py` 사례의 윤뷰스 전용 정렬·끝인사·사진 규칙은 다른 계정의 공통 형식으로 강제하지 않는다.

## 1. 착수와 직원 간 판단

먼저 최신 사용자 요청의 계정, 질문/키워드, 목적, 공개 날짜·시간(KST), 실제 자료·스티커 요구, 허용된 외부 행동을 고정한다. 사용자가 시간이나 요구를 바꾸면 현재 실행 계약을 갱신하고 이전 제안을 폐기한다. 이번 사례의 날짜·시간·이미지 수를 다음 글의 기본값으로 저장하지 않는다.

키워드 담당은 후보와 반론, 리서처는 실제 근거와 해결 가능성, 작가는 독자 흐름, 이미지 담당은 설명할 픽셀, 조립자는 표시, 독립 검수자는 사실과 구현을 확인한다. 브라우저 담당은 계정·탭 소유권을 지정하고 기존 탭을 우선 재사용한다. 다른 담당자는 같은 계정 UI를 동시에 조작하지 않는다. 회의는 역할별 결론과 불확실성을 기존 실행 산출물에 남기는 과정이며 새 스크립트·중복 원고·회의 파일을 계속 만들지 않는다.

## 2. 제작 결정표

| 판단 | 확인할 실제 근거 | 진행 기준 / 중단 기준 |
|---|---|---|
| 독자 질문·수요 | 관측 검색어/자동완성 또는 명시 요청, 조회 범위와 시각 | 관측 수요 신호와 구성한 질문을 구분. SERP 존재를 검색량으로 해석하지 않음 |
| 후보 비교 | 자유 선정이면 근거 있는 후보 3개를 keywordsMd에서 비교 | 확정 키워드는 유지. 자료가 적으면 허구 후보를 채우지 않음 |
| 상위 경쟁 | 실제 블로그 탭·정렬·시각·광고 구분·상위 3개 URL/본문/해시 | 통합검색 추천과 구분. 읽지 못한 본문·이미지는 미확인 |
| 독자 이익 | 질문 직답, 조건·예외, 정확성, 공식 검증, 실제 이미지 역할, 관측 주제 이력, 최신성 | 상대 장점도 인정. 같은 장점을 독점 차별점으로 포장하지 않음 |
| 계정 연관성·중복 | 소유 글 목록의 범위·주제 이력, 현재 공개/예약/잠금 | 부분 목록을 전수라고 하지 않음. 동일 의도·제목·시각 충돌은 해소 전 제출 금지 |
| 제작 판단 | researcher.editorialDecision와 반론 | publish=근거 있는 제작, test=좁은 의도 실험, skip=독자 이익/핵심 근거 부족 또는 중복 |
| 발행 시간 | 실제 시간별 성과가 있으면 사용, 없으면 독자 행동 가설 | 시간대 우월성을 단정하지 않음. 이번 슬롯과 정기 운영 설정을 분리 |

`editorialDecision`는 `decision`, `reason`, `readerBenefit`, `competitorFindings`, `testHypothesis`를 실행 스키마대로 기록한다. `competitorFindings`의 URL은 실제 관측 순서와 연결하고 각각의 장점·미해결 질문·채택할 구조·피할 패턴을 적는다. 넓은 키워드 상단 경쟁과 좁은 질문의 기회를 분리한다. 검색량·노출·순위·클릭 자료가 없으면 미확인이라고 한다. publish/test는 제출 승인이나 순위 예측이 아니다. test로 사실 근거 부족을 우회하지 않는다.

## 3. 근거에서 원고와 화면까지

- 실제 상위 글에서 직답·상황 분기·짧은 소제목·문단 호흡 같은 원리를 배운다. 문장·비유·체험을 복제하지 않는다. 기존 상위 글에 있는 예외 설명을 새 차별점이라고 하지 않는다.
- 중요한 사실은 실제 원문의 대상·시점·조건·예외와 연결한다. 법령/행정 안내는 접수 요건과 최종 인정, 임시 대체 서류와 면제, 일반 원칙과 개별 확인을 구별한다. 원문의 내용 기준일과 조사 확인일을 나누고 계정의 공개 링크 정책을 유지한다.
- 원고는 짧은 첫 답 → 독자 조건 → 필요한 설명 → 다음 행동으로 자연스럽게 연결한다. 이 순서도 주제에 따라 조정하며 고정 소제목·FAQ·문장/사진 수를 강요하지 않는다. 내부 작업 지시·출처 번호·미확인 약속을 본문에 남기지 않는다.
- 실제 화면이 필요하면 researcher의 `captureRequests`와 공식 원문을 바탕으로 호스트가 실제 캡처한다. 요청·확보·해시 검증·픽셀 검수·삽입·전체 문서 검수는 별도 상태다. 파일명·capturedAt·URL만으로 시각 검수를 통과시키지 않는다.
- 현재 실제 자료 가져오기는 검증된 `source:capture` manifest 경로를 사용한다. 계정 경로·PNG/JPEG 실제 형식·SHA256·공식 URL·관측 설명·민감정보 부재를 검사한다. 필수 자료는 `requiredMaterialIds`로 보존한다. 미지원 소재를 지원한다고 하거나 누락을 생성 그림으로 대체하지 않는다.
- 각 사진의 목적과 캡션은 해당 픽셀에서 확인 가능한 내용에 한정한다. 다른 사진이 담당하는 설명을 한 장에 모두 요구하지 않는다. 캡처에 생성 프롬프트나 가짜 표/기관 UI를 합성하지 않는다. 캡처는 관련 설명 옆에 유동 배치하고 캡션은 한 번만 표시한다.
- 사용자가 스티커를 요청하면 현재 호스트가 검증한 무료 내장 스티커를 `decorationPlan`으로 연결한다. 현재 계약은 0~1개이며 호스트가 ID/해시를 바인딩한다. 본문을 가리거나 공식 증거를 대신하지 않는다. 유료 결제나 새 상품 도입은 별도 권한 없이 하지 않는다.
- 호스트는 승인된 문서를 실제 편집기 화면 위에서 아래로 순서대로 입력한다. 제목·본문·서식·이미지·전용 캡션·스티커의 실제 적용을 확인한다. 숨은 HTML 교체나 미리보기 통과를 실제 네이버 입력 검증으로 대체하지 않는다.

## 4. 자율 교정과 보고 경계

현재 자동 교정은 두 경로로 제한한다. 키워드 제목 정합이 `exact_subject` 또는 `direct_subtask`이고 제목에 질문의 과업만 빠졌다면, 측정 검색어·독자 질문·최초 readerGoal을 고정한 채 제목만 1회 교정하고 새 정합 검수를 받는다. 무관하거나 불확실한 관계는 보류한다. 별도로 작가 단계가 승인된 뒤 assembler/reviewer의 구조화된 거부에 대한 최소 교정은 1회만 허용한다. 각 경로의 예산은 실제 발행에서는 동일 계정·날짜·슬롯, 준비 전용에서는 해당 폴더에 내구성 있게 기록하며 서로 분리한다. 이 두 교정 경로는 합계 최대 2회이며 외부 재시도로 예산을 초기화하지 않는다. 초기 이미지 픽셀 실패나 편집기 입력 후 검수 실패를 이 교정 범위에 포함시키지 않는다.

별도로 계정만 지정한 자유 선정에서는 후보 대체를 1회 허용한다. 실제 작가 독립 검수에서 질문 정합은 true이지만 본문이 핵심 과업에 답하지 못하고, 실제 수집 출처의 부족도 별도 독립 판정으로 확인된 경우에만 적용한다. 사용자가 주제·검색어·자료·근거 입력을 고정했거나 제출 결과가 불명확하거나 제출을 시작한 경우에는 대체하지 않는다. 실패한 동일 핵심 의도·질문을 다시 선택하지 않는다. 큰 검색어를 공유한다는 이유만으로 거부하지 않으며, 정규화한 정확히 같은 질문은 호스트가 거부하고 독립 정합 검수의 `distinctFromExcludedTasks:true`로 기존 제외 과업과 실질적으로 다른 질문임을 확인한다. 미판정 또는 false이면 보류한다. 대체 후보의 실제 상위 3개 본문·출처·모든 후속 검수는 새로 수행한다. 미승인 원본과 실패 근거는 보존한다. 후보 대체 예산은 앞의 제목 1회·후속 교정 1회와 별개이며, 실제 발행에서는 동일 계정·날짜·슬롯에 지속되고 준비 전용에서는 최초 실행 폴더의 예산을 새 후보에도 이어받는다. 후보나 폴더를 바꾸거나 외부에서 재시도하여 이 1회 제한을 초기화하지 않는다.

승인된 목적·계정·일정·비용 범위 안의 후보 선택, 자료 조사, 문단·이미지 배치, 허용된 무료 장식과 근거 있는 최소 교정은 직원이 판단한다. 매번 사용자에게 일상적 선택을 되묻지 않는다. 선택 이유와 반론은 기존 실행 산출물에 남기고, 아래의 실제 예외만 구체적으로 보고한다. 선택적인 이미지가 없어도 답이 충분하면 장식 수량을 채우지 않고 진행할 수 있다. 필수 자료나 핵심 사실의 부재와 구분한다.

| 상황 | 담당자가 할 일 | 완료 또는 보고 조건 |
|---|---|---|
| 제출 전 명확한 사실/문구/배치 결함 | 실패 원본과 이유 보존, 근거 확인 후 해당 부분 최소 교정 | 영향받은 단계부터 새 실제 독립 검수, 변경된 해시로 전체 화면 재검수 |
| 검수자가 근거 없다고 했으나 원문에 존재 | 정확한 원문 위치와 관련 조건을 재확인하여 새 검수 입력에 연결 | 승인값 수정 금지. 반려 기록 보존 |
| 같은 원인으로 교정 후 다시 실패 | 새로운 관측 없이 같은 작업 반복하지 않음 | 원인·시도·남은 결함·가능한 다음 행동을 구체적으로 보고 |
| 필수 자료/공식 조건 미확인, 계정/로그인/보호조치, 권한 밖 비용·범위 | 실행 가능한 안전한 읽기 조사까지만 수행 | 필요한 정보나 사용자 행동을 명시, 성공/승인을 꾸미지 않음 |
| 제출 시작 후 응답 불명 | 기존 편집기·원장·응답 보존, 읽기 대조 | 재클릭/강제 재실행 금지. 공개·예약 결과가 확인되기 전 unknown 유지 |

독립 검수는 생성자가 자신의 합격값을 쓰는 단계가 아니다. 무관한 승인 재사용·원장 플래그 변경·TTL/잠금/쿨다운 우회는 허용하지 않는다. 회복 가능한 결함은 담당자가 먼저 구체적으로 고치되, 권한·사실·제출 결과가 불명확하면 임의 결정하지 않는다. 이 절차가 있다는 사실만으로 아직 연결되지 않은 자동 재진입 기능이 구현되었다고 보고하지 않는다.

## 5. 제출과 결과의 진실

1. 최신 계정·날짜·시간·제목, 활성 작업/잠금, 공개/예약 중복, 제출 권한을 재확인한다. 기존 브라우저를 재사용하며 필요한 경우에만 승인된 Windows BAT 또는 Ubuntu 계정별 전용 launcher를 사용한다.
2. PC와 모바일에서 제목부터 마지막까지 실제 검수하고 승인 본문·사진·캡션·장식 해시 및 적용된 카테고리/공개 설정을 확인한다. 변경되면 새 검수를 받는다.
3. 클릭 전에 submitting을 내구성 있게 기록하고 한 번만 제출한다. 응답 불명은 실패 확정이나 재제출 허가가 아니다.
4. 정확한 계정·제목·KST 날짜/시간과 서버 문서 식별자를 두 번의 독립된 최신 예약 목록에서 확인하고 저장 원고를 다시 열어 승인 내용과 대조한다.
5. 증거가 있을 때만 검증된 예약으로 기록한다. 예약, 실제 공개, 검색 노출, 클릭/유입은 별도 결과다. 일회 완료로 일일 timer/미정 슬롯까지 자동 운영 중이라고 하지 않는다.
6. 원본/검수/제출 증거는 private output에 보존하고 민감정보 없는 상태만 동기화한다. 사용자 탭은 보존하고 직접 만든 완료 탭만 정리한다. 불명 결과 탭은 보존 이유를 남긴다.

## 실행 산출물과 기존 도구의 범위

현행 실행은 `pipeline_runner.py`와 그 단계별 JSON/handoff를 기준으로 한다. `keyword-selector.json`, `researcher.json`, `writer.json`, 이미지 계획·실제 파일, 조립 결과, 독립 검수, 실제 편집기 관측과 예약 증거를 각 실행 폴더에서 연결한다. 모델이 입력으로 받은 JSON은 실행 명령이 아니며 모델 응답을 임의 shell 명령으로 실행하지 않는다.

`document_checks.ok`는 제공된 형식 검사 결과이며 출처 진위·실제 픽셀·실제 네이버 입력·제출 결과를 대신하지 않는다. `pre-reservation-review.json`의 `account`, `title`, `reserveTime`, `pcWholeDocumentVisualReview`, `mobileWholeDocumentVisualReview`, `screenshots`, `documentSha256` 등은 실제 호스트 관측과 현재 문서에 연결한다. 장식이 있으면 현재 실행의 장식 해시도 검증한다. 화면을 보지 않고 완료 값을 생성하지 않는다.

과거 `posting.py validate/render`는 별도의 문서/사진 계획을 검사하고 오프라인 HTML 미리보기를 만드는 도구다. 그 도구의 `ready_for_handoff`는 실제 발행 완료가 아니며, 과거 윤뷰스 고정 정렬·끝인사·사진 사례를 모든 계정에 적용하지 않는다. 현재 파이프라인이 실제 브라우저 입력/예약을 제공하는데도 과거 문서의 '브라우저 자동 실행기 없음'을 현재 상태로 인용하지 않는다.

계정별 페르소나·서체·독자·호흡은 `soul.md`와 현재 프로필에 따른다. 모바일 의미 단위 줄바꿈, 실제 서체/크기, 소제목·캡션·장식·끝맺음을 확인한다. 승인된 글의 정확한 입력 비교는 누락과 변경 검증을 위한 것이며 다른 글과 문장 유사도를 맞추는 문체 템플릿이 아니다.

캡처 요청의 anchors에는 observation이 주장하는 모든 필수 조건·대체 조건을 포함한다. 일부 문구를 찾았다는 이유로 전체 표나 모든 예외가 보인다고 쓰지 않는다. 표/목록의 끝과 문장 잘림을 실제 픽셀로 확인하고, 필요한 범위가 잘리면 새 캡처와 독립 검수를 받는다.
